# PPT 制作工作流

按阶段执行；每阶段有明确产出和检查点，未过检查点不进入下一阶段。
档位与配色预设（`--tier` / `--preset`，真源 `profiles.json`）在阶段 0 定下，全程沿用。

## 阶段 0 · 接单与边界
- 输入：用户材料（Word / 源 PPT / 参考截图 / 口头要求）、页数与交付形式（整套 or 单页）。
- **定档位与预设**：正式评审/答辩/学术组会 → `strict`；常规汇报 → `balanced`；内部草稿 → `fast`。配色默认预设 A，用户点名或场景需要时换 B/C。
- 先读材料再动手；要求已明确就不追问，只在缺关键事实时问一句。
- 确认并记住红线：**不调用 PowerPoint COM、不碰用户打开的窗口；不覆盖正在编辑的源文件；中间产物进临时目录。**

## 阶段 1 · 材料与数据
- 从 Word/课件抽取全部可用数据，保留出处（表号/段号），区分**最新口径**与课件旧口径，旧数据按最新替换。
- 为每页提炼**一个核心判断**（一句话），并把它写成**命题式标题**。
- 输出：每页的"标题 + 核心判断 + 3 条实证（指标名与数值同句）+ 1 个图表数据集"。
- 检查点：每个数字都能回到原材料原文；不自造词、不编数据。

## 阶段 2 · 先写大纲（硬门槛，不确认不生成）
- 输出一页纸大纲（表格）：**页码 / 命题式标题 / 核心判断 / 上片的实证 / 图形形式（图表/表格/关系图）/ 讲稿要点与时长**。
- 另列**待确认事项**：听众与深度、总时长、是否需要代码页、是否需要手推推导页。
- 每个数字标注来源与口径；来自实算的注明"由脚本实算"。
- 检查点：用户确认（或自查通过）后才进入版式设计；结构要改先改大纲。

## 阶段 3 · 版式设计
- 选结构：**强数据、强主题 → 表格**；叙事/机制/并列 → 方块/方格，块内直接写内容，不加段落小标题。
- 定骨架（同批页面一致；骨架种类按 `layout-patterns.md` 的关系模型库选）：页眉 14pt 极浅灰 → 页眉发丝线 → 标题 30pt → 副标 20pt → 正文区 → 结论行（有独立结论价值时）。字号只走字阶 `14(HF 档) / 16 / 18 / 20 / 30 / 36 / 44`。
- 左文右图页：左栏 = 3 条 18pt 实证（关键数值黑体墨色）→ 发丝线 + 黑体判断行；右栏 = 图表 + 两行图注（结论句 + 口径句）。
- **装饰预算按档位**：strict 无装饰图形、无几何记忆点；fast/balanced 允许淡卡片、编号与（仅 fast）图标/章节母题，见 `effect-budget.md`。
- 检查点：每页有明确视觉手段（图表/表格/图片/版面结构）；密度可控（实证 1–2 行、判断 2–3 行、下缘留白）；图表坐标轴留余量，标签不贴边。

## 阶段 4 · 生成
- 用脚本生成 pptx（python-pptx）：字号只走字阶、文字只用当前预设 token（默认 黑/`6E6E6E`/`0072B2`）；**两槽都显式写**——中文进 `a:ea`（宋体/黑体/楷体），西文进 `a:latin`（Arial / Times New Roman），黑体不再叠加粗体。
- 单页单独输出文件，不覆盖源文件。
- 每页备注写入：**约 1 分钟逐字稿 + 口径备答**（来源、年份、统计口径）。

## 阶段 5 · 四道自检
0. 结构审查：`scripts/audit_ppt.py <文件...> --tier <档位>`——越界、文本溢出、西文不可断行、表格单元格撑高、元素重叠、字体槽、字形缺失、全角西文、备注、表宽、阴影特效、配图分辨率、布局骨架；有项先修再往下走。
1. 机器校验：`scripts/verify_ppt_style.py <文件...> --tier <档位> --preset <预设>`——字阶档位与每页档数、预设 token 配色与对比度、点缀限额、图表配色、中文/西文双白名单、黑体加粗、楷体入表格、前缀与口径，必须全 OK（或统一走 `check_ppt.py` 一次过）。
2. 视觉校验：`scripts/preview_ppt.py <文件> <输出.html> --slide N`（0 基）→ 截图，逐页看**溢出、重叠、对齐、密度、形状是否成形**。
3. 内容校验：数字与原材料逐条对照；无自造词；标题不口水；口径在备注不上片。
- 检查点：四道全过才交预览图给用户。

## 阶段 6 · 交付与版本
- 先发**预览图**给用户确认，按反馈改，改完重跑阶段 4。
- 纳入版本管理时：只 `add` 本次交付文件 → 中文 commit message → push；**不提交用户自己在改的文件**。
- 汇报格式：每个文件的绝对路径 + 每页要点 + commit hash。

## 常见返工触发（出现即改）
- 内容结构被推翻 → 回**阶段 2 大纲**改，再改页面；不要在成稿上改结构。
- 大纲没确认就开做 → 立即停下补大纲（这是最容易产生返工的一步）。
- 文字太密 → 减字不缩字号；加图表、改结构。
- 页面雷同 → fast/balanced 档换视觉手段（图表/表格/图片），strict 档靠内容差异与留白，骨架可保持不动。
- 出现段落小标题 / 指标与数值分层 → 删标签、合并成一句。
- 出现预设 token 之外的文字色，或正文小于档位下限 → 立即回改。
- 数据口径陈旧 → 回阶段 1 换最新口径。
