# PPT 制作与改版工作流

按阶段执行；每阶段有明确产出和检查点，未过检查点不进入下一阶段。规则阈值见各专项文件，本文件只描述流程顺序与检查点。

## 阶段 0 · 接单与边界
- 输入：用户材料（Word / 源 PPT / 参考截图 / 口头要求）、页数与交付形式（整套 or 单页）。
- 先读材料再动手；要求已明确就不追问，只在缺关键事实时问一句。新建整套演示前，先一次性问清配色、素材、风格和特殊要求（见 `SKILL.md`）。
- 确认并记住红线：**不调用 PowerPoint COM、不碰用户打开的窗口；不覆盖正在编辑的源文件；中间产物进临时目录；不使用 SmartArt。**

## A. 新建完整演示

1. **主动问细节**：配色、素材、风格、特殊要求、受众、汇报时长、逐字稿要求。
2. **整理材料**：抽取全部可用数据，保留出处、年份与统计口径，区分最新口径与课件旧口径。
3. **确定规模**：用户未指定时默认 **10～15 页**；用户指定页数时服从用户。
4. **规划配图**：按 `references/image-sourcing.md` 给每页定必要性分档，一次性完成候选素材盘点；此时不锁定最终分配。
5. **制作大纲（硬门槛）**：每个数字标注来源与口径，由实算的注明"由脚本实算"。
6. **用户确认**：结构未确认前不生成整套页面；确认后再定最终配图分配与母题；单页任务不需要完整大纲。
7. **生成演示**：按 `references/palette-system.md` 与 `references/layout-patterns.md` 选配色和骨架，不强制每页配图或加装饰。
8. **检查**：跑 `scripts/check_ppt.py`，再打开预览逐页复核。
9. **交付**：先给预览和修改摘要；用户反馈后重新生成并重跑检查。

### 大纲字段（阶段 A5）

表格每页一行：**页码 / 命题式标题 / 核心判断（一句话）/ 上片的实证 / 关系模型与页面骨架 / 视觉手段 / 讲稿要点与时长**。

表外再列：

- **章节视觉母题**：章节 / 母题名称 / 图形语言 / 使用强度 / 与内容关系的匹配理由（见 `references/effect-budget.md`）。
- **配图计划**：必要性分档与候选素材（见 `references/image-sourcing.md`）。
- **待确认事项**：听众与深度、总时长、是否需要代码页或手推推导页。

检查点：用户确认（或自查通过）后才进入版式设计；结构要改先改大纲，不要在成稿页面上改结构。

### 生成时的硬性写法（阶段 A7）

- 用脚本生成 pptx（python-pptx）：字号只走字阶 **`16 / 18 / 20 / 30 / 36 / 44`**。
- **两槽都显式写**：中文进 `a:ea`（宋体/黑体/楷体），西文进 `a:latin`（Arial / Times New Roman），黑体不再叠加粗体。
- 文字颜色黑白灰为基础色，加上主题色系列、对比色、辅助色的既定档位；内容变多时**减字，不缩字号**。
- 单页单独输出文件，不覆盖源文件。
- 每页备注写入：**约 1 分钟逐字稿 + 口径备答**（来源、年份、统计口径）。

### 四道自检（阶段 A8）

0. **结构审查**：`scripts/audit_ppt.py <文件...>`——越界、文本溢出、西文不可断行、表格单元格撑高、元素重叠、字体槽、字形缺失、全角西文、备注缺失、表宽、布局骨架、配图、禁用对象；有问题先修再往下走。
1. **机器校验**：`scripts/verify_ppt_style.py <文件...>`——字号（含字阶档位与每页档数）、配色方案、对比度、色相组数、面积配额、中文/西文双白名单，必须全 OK。
2. **视觉校验**：`scripts/preview_ppt.py <文件> <输出.html>` → 截图，逐页看**溢出、重叠、对齐、密度、形状是否成形**。
3. **内容校验**：数字与原材料逐条对照；无自造词；标题不口水；口径在备注不上片。

也可以直接跑统一入口 `scripts/check_ppt.py`，它调度上面两个检查脚本并汇总分级结果。

## B. 模板跟随改版

按 `references/template-editing.md` 的四步执行：

1. **提取素材和配色**；
2. **分析 PPT**；
3. **选取页面重新设计**；
4. **风格复核，是否与原来风格一致**。

只修改选定页面，输出新文件并附变更说明。继承原模板配色时，把原配色映射到"黑白灰基础色 + 主题色系列 + 对比色 + 辅助色"四类，再判断继承色是否满足对比度。原模板已有 SmartArt 保持原状并提示，沿用原模板时用 `--allow-smartart` 声明。

## C. 单页调整

1. 确认目标页面和修改范围；
2. 写一句变更摘要，不做完整大纲；
3. 只修改目标页；
4. 运行检查并输出预览。

## D. 合规检查

1. 询问重点检查项；
2. 运行 `scripts/check_ppt.py`（可选 `--mode strict`、`--json`、`--layout-report`）；
3. 打开预览逐页复核；
4. 按错误、警告、建议和例外输出问题清单；
5. 不自动修改，除非用户要求。

## 数据与内容

- 每个数字必须能回到用户材料或实算结果。
- 材料没有最新数据时标明缺口，不自行搜索后静默替换。
- 旧口径需要保留时明确标注历史口径。
- 来源、口径和备答默认进备注；需要公开核验时在片上保留简短出处。

## 检查点与返工

- 大纲没确认就开做 → 立即停下补大纲（这是最容易产生返工的一步）。
- 结构被推翻 → 先改大纲再改页面，不要在成稿上改结构。
- 出现连续三页同一骨架、方块页过半、纯文字页超过两成 → 换骨架或换关系模型。
- 出现方案外颜色、浅底浅字、小于 16pt 正文 → 回改配色与字号。
- 配图分辨率不足或带水印 → 回配图环节换图，不用拉伸和锐化硬撑。
- 页面雷同 → 换关系模型与骨架，而不是只换记忆点形状。
- 出现段落小标题、指标与数值分层 → 删标签、合并成一句。
- 需要保留的合理例外 → 在备注写 `[例外:…]` 理由，或用 `--exceptions` 记录，不要直接忽略检查结果。

## 安全与版本

- 不覆盖用户正在编辑的源文件。
- 不调用 PowerPoint COM，不操作打开的 PowerPoint 窗口。
- 中间文件放临时目录。
- 不自动 Git add、commit、push 或切换分支；用户明确要求时另行执行。
- 不使用 SmartArt；新建或重设计页面使用普通文本、表格、形状或图表。源文件已有 SmartArt 保持原状并提示。
