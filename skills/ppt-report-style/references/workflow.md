# PPT 制作工作流

按阶段执行；每阶段有明确产出和检查点，未过检查点不进入下一阶段。

## 阶段 0 · 接单与边界
- 输入：用户材料（Word / 源 PPT / 参考截图 / 口头要求）、页数与交付形式（整套 or 单页）。
- 先读材料再动手；要求已明确就不追问，只在缺关键事实时问一句。
- 确认并记住红线：**不调用 PowerPoint COM、不碰用户打开的窗口；不覆盖正在编辑的源文件；中间产物进临时目录。**

## 阶段 1 · 材料与数据
- 从 Word/课件抽取全部可用数据，保留出处（表号/段号），区分**最新口径**与课件旧口径，旧数据按最新替换。
- 为每页提炼**一个核心判断**（一句话），并把它写成**命题式标题**。
- 输出：每页的"标题 + 核心判断 + 3 条实证（指标名与数值同句）+ 1 个图表数据集"。
- 检查点：每个数字都能回到原材料原文；不自造词、不编数据。

## 阶段 2 · 先写大纲（硬门槛，不确认不生成）
- 输出一页纸大纲（表格）：**页码 / 命题式标题 / 核心判断 / 上片的实证 / 图形形式与几何记忆点 / 讲稿要点与时长**。
- 另列**待确认事项**：听众与深度、总时长、是否需要代码页、是否需要手推推导页。
- 每个数字标注来源与口径；来自实算的注明"由脚本实算"。
- 检查点：用户确认（或自查通过）后才进入版式设计；结构要改先改大纲。

## 阶段 3 · 版式设计
- 选结构：**强数据、强主题 → 表格**；叙事/机制/并列 → 方块/方格，块内直接写内容，不加段落小标题。
- 定骨架（同批页面一致）：页眉 16pt → 标题 30pt → 副标 20pt → 细线 → 左文右图双栏 → 底部结论条 18pt。字号只走字阶 `16 / 18 / 20 / 30 / 36 / 44`。
- 左栏四段：楷体 20pt 导语 → 3 条 18pt 实证（左侧竖条）→ 黑体 18pt 判断；右栏：配图 + 图表 + **几何记忆点**。
- 每页指定一个几何记忆点，同批五页各不相同（圆 / 三角 / 圆点线路 / 环形图 / 六边形…），骨架不变。
- 检查点：每页有图表或图片；密度可控（实证 1–2 行、判断 2–3 行、下缘留白）；图表坐标轴留余量，标签不贴边。

## 阶段 4 · 生成
- 用脚本生成 pptx（python-pptx）：字号只走字阶六档、文字只 黑/白/`283E4E`；**两槽都显式写**——中文进 `a:ea`（宋体/黑体/楷体），西文进 `a:latin`（Arial / Times New Roman），黑体不再叠加粗体。
- 单页单独输出文件，不覆盖源文件。
- 每页备注写入：**约 1 分钟逐字稿 + 口径备答**（来源、年份、统计口径）。

## 阶段 5 · 四道自检
0. 结构审查：`scripts/audit_ppt.py <文件...>`——越界、文本溢出、西文不可断行、表格单元格撑高、元素重叠、字体槽、字形缺失、全角西文、备注缺失、表宽；有项先修再往下走。
1. 机器校验：`scripts/verify_ppt_style.py <文件...>`——字号（含字阶档位与每页档数）、三色、中文/西文双白名单、黑体加粗、楷体入表格，必须全 OK。
2. 视觉校验：`scripts/preview_ppt.py <文件> <输出.html>` → 截图，逐页看**溢出、重叠、对齐、密度、形状是否成形**。
3. 内容校验：数字与原材料逐条对照；无自造词；标题不口水；口径在备注不上片。
- 检查点：四道全过才交预览图给用户。

## 阶段 6 · 交付与版本
- 先发**预览图**给用户确认，按反馈改，改完重跑阶段 4。
- 纳入版本管理时：只 `add` 本次交付文件 → 中文 commit message → push；**不提交用户自己在改的文件**。
- 汇报格式：每个文件的绝对路径 + 每页要点 + commit hash。

## 常见返工触发（出现即改）
- 内容结构被推翻 → 回**阶段 2 大纲**改，再改页面；不要在成稿上改结构。
- 大纲没确认就开做 → 立即停下补大纲（这是最容易产生返工的一步）。
- 文字太密 → 减字不缩字号；加图表、加几何记忆点。
- 页面雷同 → 换记忆点形状，骨架保持不动。
- 出现段落小标题 / 指标与数值分层 → 删标签、合并成一句。
- 出现第四种文字颜色或小于 16pt → 立即回改。
- 数据口径陈旧 → 回阶段 1 换最新口径。
