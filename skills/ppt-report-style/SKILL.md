# 汇报 PPT 规范

## 定位

本 skill 是个人内容与视觉规范层，不是独立的 PowerPoint 技术引擎。

- 若环境中存在内置的 `Presentations` skill，创建、编辑、模板跟随与技术实现遵循它；本 skill 负责字体、配色、布局、配图、内容结构和讲稿。
- 编辑已有 PPT 时，原模板与用户明确要求优先于默认个人版式。
- 用户明确要求"严格按我的规范"时，按 `references/style-rules.md` 的严格档执行。
- 两个 skill 或用户要求冲突时，停下来说明冲突，不要静默选择。

## 规则优先级

规则冲突时按优先级取舍，低优先级规则不得迫使设计者违反高优先级规则。

| 优先级 | 规则 | 冲突时的处理 |
| --- | --- | --- |
| P0 | 内容准确、信息完整、可读性、版权与真实性 | 必须满足 |
| P1 | 用户明确要求、模板兼容、交付约束 | 原则上满足，例外需说明 |
| P2 | 信息关系、视觉层级、色彩对比、布局清晰度 | 尽可能满足 |
| P3 | 布局多样性、母题数量、效果预算 | 允许有依据地例外 |
| P4 | 装饰性增强、特殊形状、渐变与阴影 | 可省略 |

核心信条：**宁可没有，不能乱加。** 例外要写理由，不为通过检查而机械改页面。

## 工作模式

| 模式 | 适用 | 默认流程 |
| --- | --- | --- |
| 新建完整演示 | 新的一套汇报 PPT | 主动问细节 → 材料 → 大纲（含配图与母题）→ 确认 → 生成 → 检查 |
| 模板跟随改版 | 沿用已有 PPT 的视觉体系 | 提取素材和配色 → 分析 PPT → 选取页面重新设计 → 风格复核 |
| 单页调整 | 改一页、局部重排、压缩文字 | 变更摘要 → 修改 → 检查 |
| 合规检查 | 只检查不改稿 | 分级检查 → 问题清单 |

## 新建完整演示前先问清楚

新建一套完整 PPT 时，先一次性询问：

1. **配色**：沿用主题色系列 `#283E4E`、指定色值，还是使用现有素材色？
2. **素材**：是否有 Logo、照片、图标、图表、模板或参考截图？
3. **风格**：严谨答辩、学术汇报、简洁商务、案例展示，还是沿用旧 PPT？
4. **特殊要求**：固定模板、必须保留的页面、代码/公式/推导、答辩格式等。
5. **基本条件**：受众、汇报时长、预计页数、逐字稿要求。

除非用户另有指定，完整演示默认 **10～15 页**；用户指定页数时服从用户。

## 硬性限制

- 字体分两槽：**中文只用 宋体 / 楷体 / 黑体**（写进 `a:ea`），**西文只用 Arial / Times New Roman**（写进 `a:latin`）。字号只走下面"字阶"的 6 档，**最小 16pt**。
- 配色按 `references/palette-system.md`：**黑白灰是基础色**，不占配色额度；主题色是一个**色阶系列**（不是一个颜色），另有一个对比色和一个辅助色。灰色不得用于文字；底纹可用 `F1F5F8`，边框 `B7C1C8`。
- 正文对比度不低于 4.5:1，大字与图形边界不低于 3:1；单页色相组不超过 3 组。
- 内容变多时**减字，不缩字号**。
- 不在正文块里加"西方的问题""中国的做法""关键指标"这类段落小标题，内容直接写。
- 指标名与数值写在**同一句**里，不做"上面指标名、下面数值"的两层结构。
- 标题用命题式表述，不写口水话。
- **不使用 SmartArt**；源文件已有 SmartArt 保持原状并提示。

## 字阶与字体分工（内容 → 字体 / 字号对照表）

只有这 **6 档**：`16 / 18 / 20 / 30 / 36 / 44`。落在档外即视为层级失控，`verify_ppt_style.py` 会报"字号不在字阶内"。

| 层级 | 用在什么内容 | 中文（a:ea） | 西文（a:latin） | 字号 | 行距 | 颜色 |
| --- | --- | --- | --- | --- | --- | --- |
| 封面主标题 | 首页标题，≤12 字 | 黑体 | Arial | 44 | 1.1 | 主题色深档 |
| 章节 / 大标题 | 章节页、图形区大标题 | 黑体 | Arial | 36 | 1.1 | 主题色深档 |
| 页面标题 | 每页命题句，≤32 字 | 黑体 | Arial | 30 | 1.15 | 主题色 |
| 副标题 | 口径、范围、时间、方法说明 | 宋体 | Times New Roman | 20 | 1.2 | 黑 |
| 导语 / 引文 | 左栏首段、引用原话 | 楷体 | Times New Roman | 20 | 1.3 | 黑 |
| 正文 | 实证条、判断块、结论条 | 宋体；判断与结论换黑体 | 随中文配对 | 18 | 1.2–1.4 | 黑；判断与结论主题色 |
| 表格 | 表头黑体白字，正文宋体 | 黑体 / 宋体 | Arial / Times New Roman | 16 | 1.0–1.1 | 白 / 黑 |
| 图注 · 页眉 · 页码 · 图形内文字 | 辅助信息 | 宋体 / 黑体 | Arial | 16 | 1.0–1.1 | 主题色 / 黑 / 白 |
| 大数字块 | 圆、六边形内的统计数值 | — | Arial | 36–44 | 1.0 | 主题色 |

- **一页最多 5 档**（六档里取，落地一页通常 3–5 档）。同一层级全篇同档，不许这页 18、下页 19。
- 标题与正文的比例：页面标题 30 ÷ 正文 18 ≈ 1.7，封面 44 ÷ 18 ≈ 2.4；网络常见区间 1.8–2.2，命题式长标题取低值以免换行。
- **16pt 是硬下限**，比网络常见的 14pt 更严——投影后排可读优先，放不下就减字。页码、脚注、资料来源同样不低于 16pt。
- 字重：黑体**不再叠加粗体**（合成粗会糊边），宋体、楷体不加粗；强调一律"换黑体 + 主题色"。
- 楷体每页最多一处（导语或引文），不进表格、不进图形。
- 数字随文走：正文里的数字用该行配对的西文字体（宋体语境 → Times New Roman）；独立大数字块一律 Arial。

## 中英混排（英文、数字、缩写）

- **两槽都要显式写**：python-pptx 的 `run.font.name` 只写 `a:latin`（西文槽），中文字形取 `a:ea`。只设 `font.name="宋体"` 会让英文用宋体的西文字形渲染——字距松、字形丑，而且旧版校验查不出来。
- 配对建议（非硬性，但同一页内保持一致）：黑体 → Arial；宋体 / 楷体 → Times New Roman。不要一行 Arial、一行新罗马混着排。
- 中文与英文、数字之间加一个半角空格：`11 个项目`、`前 20 秒`；纯英文短语内部不加。
- 英文字母与数字一律半角，禁止 `ＢＰＭ`、`２０２４`；全角只留给中文标点。
- 括号按外层语言选：中文句子里用 `（app.py）`，不写成 `(app.py）`。
- 缩写首次出现给中文全称：`MIR（音乐信息检索）`；表格里可只留缩写，口径写进备注。
- **长英文 token 是溢出主因**：`conversation_log.csv` 这类无空格串不能逐字断行，只能整体换行。放进宽栏、手动用空格或 `·` 断开、或改写成中文；不要指望缩字号解决。
- 不为代码或文件名引入第三种西文字体；需要等宽效果就改写成中文描述，或放截图。

## 配色体系

- **中性色（黑 / 白 / 灰）是基础色，不占配色额度**：正文用黑，底色与分区用灰与浅主题色，边框 `B7C1C8`。
- **主题色是系列不是单色**：默认 `#283E4E` 的七档 `#142129 #1E303B #283E4E #4A6577 #8199A8 #B7C7D2 #E4EBF0`；用户指定"红色"时要给出同一个色相的多档深浅，而不是一个色值。
- **对比色**默认暖琥珀四档 `#8C5A16 #B4771F #C98B2E #E0B15B`，只用于关键强调，面积最小。
- **辅助色**默认灰青绿四档 `#2F4E48 #4F7C74 #8DB0A8 #D6E5E1`，用于分区、次要系列和附属信息。
- 深浅档要按用途分配：深档承载标题、正文与描边，中档做图形填充，浅档只做背景与弱化。**浅档不能承载正文小字**（`#8199A8` 相对白底只有 2.98:1）。
- 配色不得"太丑、对比度爆炸"：先保证关系清楚、视觉克制，再谈变化。完整规则见 `references/palette-system.md`。

## 先大纲，后页面（硬门槛）

- **生成任何页面之前，先写一版一页纸大纲**并交用户确认（或至少自查一遍）再动手。
- 大纲用表格，每页一行：**页码 / 命题式标题 / 核心判断（一句话）/ 上片的实证 / 关系模型与页面骨架 / 视觉手段 / 讲稿要点与时长**。
- 表外再列：**章节视觉母题**（见 `references/effect-budget.md`）、**配图必要性分档与候选素材**（见 `references/image-sourcing.md`）、**待确认事项**（听众、时长、是否加代码页、是否加推导页）。
- 大纲里每个数字都要能追溯到材料或实算结果，标注口径与出处。材料缺少最新数据时明确标缺口，不自行编造或静默替换。
- **内容结构一旦要改，先改大纲再改页面**，不要在成稿页面上改结构——那是返工最多的一种改法。
- 大纲未确认，不进入生成阶段；单页调整与合规检查不强制完整大纲，只写简短变更摘要。

## 布局与视觉手段

- 按 `references/layout-patterns.md`：**先判断内容关系，再选骨架**。关系模型至少覆盖 4 种（对比、流程、层级、循环、时间线、辐射、矩阵等），连续 3 页不得使用同一主骨架，方块矩阵类页面不超过约 35%。
- 按 `references/visual-means.md`：**每页至少一种视觉手段**，手段可以是关系图、图表、图片、表格、大数字、多级字号、留白与重心偏移；不要求每页都画示意图。
- 元素关系要有多样性：允许斜向、层叠、环绕、路径连接，不必全部水平垂直摆放；坐标仍按 0.05in 网格对齐。
- 主视觉形状按语义选择圆形、平行四边形、圆柱、三角形、六边形，不把所有页面都做成方块矩阵堆叠。
- 结论条**按具体内容设置**，只有页面需要独立收束判断时才用，不作为统一骨架要求（见 `references/style-rules.md`）。

## 效果预算与母题

- **每章一个视觉母题，章节之间切换**：例如第一章用弧线语言，第二章用层叠面，第三章用圆形节点。母题是同一章共享的图形语言，不是"每页必须出现同一个元素"。
- 母题数量是**软建议**：默认 3 个、建议不超过 5 个，章节多时允许超过，但要在大纲里写明每个母题对应的章节。
- 每页最多 **1 个主效果 + 1 个辅助效果**，都可以省略到 0；效果强度不得超过内容层级。
- 禁止无意义渐变、阴影堆叠、发光、倒影，以及为凑视觉而加的装饰。详见 `references/effect-budget.md`。

## 配图

- 先按 `references/image-sourcing.md` 判断**必要性分档**：必须实景 / 建议配图 / 可用图表替代。只有"必须实景"档才值得投入完整搜索链路，找不到就停下来问用户。
- **在大纲阶段一次性批量盘点**候选图片，大纲确认后再定最终分配，避免返工。
- 搜索优先级：用户材料 → 本地素材库 → 官方机构或权威来源 → 开放图库（Wikimedia 等）→ 可授权图库 → 新闻媒体。
- 分辨率按**实际放置尺寸 × 裁切比例 × 目标展示分辨率**判定：有效分辨率低于约 150 dpi 提醒、低于约 96 dpi 报错。**分辨率不等于清晰度**，还要看水印、压缩痕迹与裁切损失，不放低画质、有水印的图。
- 外部图片落盘缓存并内嵌使用，记录来源、作者、许可证、访问日期与使用页面；生成图不得当作真实事件或真实人物的记录。

## 表格与方块的取舍

- **强数据类型、强主题的内容用表格**（对齐的行列结构，适合指标对比、口径对照）。
- 叙事、机制、并列要点用**方块/方格**，块内直接写内容。
- 不要把两种结构混在同一页里各占一半。

## 页面骨架

- 左边距 0.55in，正文宽约 12.96in。纵向网格（14.06×7.91in 页面，已实测过审）：页眉 `T=0.24 H=0.34`（16pt）→ 标题 `T=0.56 H=0.66`（30pt 主题色）→ 副标 `T=1.26 H=0.46`（20pt）→ `#283E4E` 细线 `T=1.76` → 正文区 `1.86–6.67` → 结论条 `T=6.80 H=0.62`（仅在需要时使用）。
- 框高按字号反推：单行需要 `字号 × 1.2 × 1.18`，20pt 至少 0.46in、18pt 至少 0.42in、16pt 至少 0.38in；照抄旧稿的 0.28–0.36in 小框会被判溢出。
- **左文右图双栏是推荐骨架之一**（左约 7.1in、右约 5.7in、间距 0.2in）：左栏 = 楷体导语块（20pt）→ 3 条实证（18pt，每条左侧 0.045in 主题色竖条）→ 黑体判断块（18pt 主题色）；右栏 = 配图 + 图表 + 图形结构。也可用全宽单栏、上下分区、网格/矩阵、主图+侧栏、中心辐射等骨架。
- 结论条默认位置为底部通栏（0.045in 竖条 + 18pt 黑体一句判断），但**是否使用由内容决定**，位置也可放在相关证据块之后。
- 强调块统一为浅底 `F1F5F8` + 左侧主题色竖条，不做全包边框。

## 密度与几何

- 实证条 1–2 行，判断块 2–3 行；行距按字阶走（标题 1.1–1.2、正文 1.2–1.4、表格 1.0–1.1），块间约 0.1in 均匀缝隙，页面下缘留白不填死。
- **每页至少一种视觉手段**；同批页面的页眉、栏宽、字号保持一致——统一中求变化。视觉承载物的形状不必每页相同，按 `references/style-rules.md` 的形状表按语义选择。
- 图表坐标轴留余量，数值标签不贴边、不被裁；几何形状与文字块中线对齐，不压字。
- 图片按框**裁切填满**，不拉伸变形，边缘与文字块对齐。

## 纯文字页

- **允许纯文字页**：核心观点页、引用页、转折页、结尾页强行配图反而削弱力量。
- 但纯文字页必须有明确的排版结构：字号层级、留白、对齐方式至少占其二，**不得只是一大段文字居中放置**（脚本会报 `LAY.PURETEXT_FLAT`）。
- 纯文字页占整套建议不超过 **15%～20%**；超出时考虑拆分或补视觉手段。
- 纯展示页、图片页、流程步骤页等没有独立落点的页面**不要加结论条**。

## 内容与备注

- 数据只来自用户提供的材料（Word/课件/来源文件），不编造、不自造词；旧数据按材料里的最新口径更新。
- 数据来源、口径、备答写进**备注**，不上片；需要公开核验时在片上保留简短出处。
- 先按整场时长分配每页讲稿，再写逐字稿；核心内容页通常按 45～90 秒（约 1 分钟）规划，封面、目录、章节页、附录页按实际讲解需要写。
- 备注不要求每页机械达到固定字数；默认门槛 150 字/页可用 `--notes-min` 调整。

完整分阶段流程（接单 → 材料与大纲 → 生成 → 四道自检 → 交付）见 `references/workflow.md`；模板跟随见 `references/template-editing.md`；检查分级与例外见 `references/checking.md`。

## 字符与记号（避免豆腐块与歧义）

- 中文字符一律限制在 **GBK 可编码范围**：宋体/黑体/楷体都能覆盖 GBK，超出就可能出现豆腐块。交付前用 `scripts/audit_ppt.py` 的"字形缺失"项兜底。
- **数学上下标写成 ASCII**：`V^T`、`s1`、`si`、`1e-8`、`O(nk^2)`；不要用 `ᵀ`、`₁`、`²`、`⁻⁸` 这类字符（宋体很可能没有）。
- 生成脚本里的**强调标记不要用 `[[ ]]`**（会与矩阵记号 `[[1,2],[3,4]]` 冲突），用 `{{ }}`。
- 公式块优先用"大字 + 短句"表达，不要用长行 ASCII 公式。

## 图表与几何细节

- 数值标签设为外侧端点（OUTSIDE_END）时，**给坐标轴留余量**：把轴上限设为最大值的约 1.2 倍，否则标签会贴边或被裁。
- 类别多时（≥4 类）柱宽要留间隔，避免柱子挤成一条线；条形图同理。
- 散点图把 `scatterStyle` 设为 `marker`，否则默认会带连线。
- 形状几何：圆/三角/六边形等纯色块放满标题栏或作为统计块；白底描边图形（圆→椭圆示意）必须显式描边，否则在白底上"消失"。
- 同一页里所有形状的坐标以 **0.05in 为网格对齐**，视觉才成体系。
- 多系列图的系列颜色从主题色阶中取，深浅自带区分度；只有在系列确实难以区分时才引入纹理或形状编码。

## 交付前机器审查（先跑脚本，再看预览）

```text
python scripts/check_ppt.py 你的.pptx           # 统一入口：调度下面两个检查，按错误/警告/建议/例外汇总
python scripts/audit_ppt.py 你的.pptx           # 越界/溢出/西文不可断行/重叠/字体槽/字形/备注/表格/布局/配图/禁用对象
python scripts/verify_ppt_style.py 你的.pptx    # 字号/配色/对比度/色相组数/面积配额/中文(ea)与西文(latin)双白名单
python scripts/preview_ppt.py 你的.pptx out.html # 全页 HTML 近似预览；--slide N 只看单页
```

- 宽度估算：中文按 1.0 em，西文按字符分类（`i l` 0.30、数字 0.58、大写 0.72、`M W` 0.90），并**按"只在空格与中文处断行"模拟真实换行**；宁可估宽，不要漏报。**宁可略留余量**，框高留 10% 保险。
- 表格单元格按栏宽单独算换行：单元格被撑高会压到下方图形，这类问题只有预览图能看出来——审完脚本必须再看一眼预览。
- 字体槽检查会分别报：`a:ea` 缺失或不在中文白名单、`a:latin` 填了中文字体（英文将用中文字形渲染）、`a:latin` 不在 Arial/新罗马之内。
- 跑历史文件时可加 `--allow-cjk-latin` 放行西文槽的中文字体；新稿不要加。
- "文本重叠"只比较**有文字**的形状之间的交集，占小块面积 >18% 才算问题。
- 布局分类是保守估算：脚本报 `LAY.*` 不代表内容关系错，只代表该页没有可识别的结构；最终以人工审阅为准。
- 自动检查不能代替打开 PPT 后的视觉复核。

## 检查分级与例外

- 结果分三级：**错误**（必须修复）、**警告**（需人工确认）、**建议**（可选优化）；每条带稳定规则 ID、页码或对象位置、实际值与预期值、修复建议。
- 结构性例外用参数声明：沿用原模板保留 SmartArt 用 `--allow-smartart`。
- 页面级例外在备注写 `[例外:骨架重复]` 等标记并说明理由；长期例外写进 JSON 用 `--exceptions` 传入，命中后降级为"例外"并在报告中保留。
- 例外不会降级安全、版权与可读性规则：对比度、字号、缺失图片和禁用对象仍然报错。
- 详见 `references/checking.md`。

## 依赖（缺失时安装）

- 必需：`python-pptx`（生成与校验）。安装：`python3 -m pip install python-pptx`，有 `uv` 时优先 `uv pip install python-pptx`。
- 可选：Playwright + Chrome（把 `scripts/preview_ppt.py` 产出的 HTML 截成图片）；缺浏览器时直接把 HTML 交给用户打开，或用 Chrome/Edge 的 headless 截图。
- 字体：宋体/楷体/黑体是中文 Office 常见字体；系统缺失时**先问用户**是否接受替代字体，不要静默替换。西文 Arial 与 Times New Roman 在 Windows / Office 默认可用。生成时两槽都要显式写，可直接抄 `scripts/build_example.py` 里的 `font(run, size, color, face, latin=None)`。

## 交付与安全

- 需要改单页时**单独输出一个 pptx**，不覆盖用户正在编辑的源文件。
- **绝不调用 PowerPoint COM 或操作用户打开的窗口**，只做文件读写。
- 改完先出预览图给用户确认，再提交；用 `scripts/check_ppt.py` 统一校验，用 `scripts/preview_ppt.py` 生成 HTML 预览。
- 纳入版本管理时只提交本次新增/修改的交付文件，不提交用户自己在改的文件；中间产物放临时目录并忽略。**不自动执行 git add / commit / push**，用户明确要求时再执行。
