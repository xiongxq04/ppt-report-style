## 中英混排（英文、数字、缩写）
- **两槽都要显式写**：python-pptx 的 `run.font.name` 只写 `a:latin`（西文槽），中文字形取 `a:ea`。只设 `font.name="宋体"` 会让英文用宋体的西文字形渲染——字距松、字形丑，而且旧版校验查不出来。
- 配对建议（非硬性，但同一页内保持一致）：黑体 → Arial；宋体 / 楷体 → Times New Roman。不要一行 Arial、一行新罗马混着排。
- 中文与英文、数字之间加一个半角空格：`11 个项目`、`前 20 秒`；纯英文短语内部不加。
- 英文字母与数字一律半角，禁止 `ＢＰＭ`、`２０２４`；全角只留给中文标点。
- 括号按外层语言选：中文句子里用 `（app.py）`，不写成 `(app.py）`。
- 缩写首次出现给中文全称：`MIR（音乐信息检索）`；表格里可只留缩写，口径写进备注。
- **长英文 token 是溢出主因**：`conversation_log.csv` 这类无空格串不能逐字断行，只能整体换行。放进宽栏、手动用空格或 `·` 断开、或改写成中文；不要指望缩字号解决。
- 不为代码或文件名引入第三种西文字体；需要等宽效果就改写成中文描述，或放截图。

## 表格与方块的取舍
- **强数据类型、强主题的内容用表格**（对齐的行列结构，适合指标对比、口径对照）。
- 叙事、机制、并列要点用**方块/方格**，块内直接写内容。
- 不要把两种结构混在同一页里各占一半。

## 页面骨架
- 左边距 0.52in，正文宽约 12.29in。纵向网格（13.33×7.5in 页面，PowerPoint 默认 16:9，已实测过审）：页眉章名 `T=0.22 H=0.36`（14pt 极浅灰 `D9D9D9`）→ 页眉发丝线 `T=0.66 H=0.005`（约 0.36pt 特细，纯直线无任何效果）→ 标题 `T=0.98 H=0.63`（30pt 墨色，与页眉线保持 0.32in）→ 副标 `T=1.96 H=0.44`（20pt）→ 正文区 `2.55–6.05` → 结论发丝线 `T=6.15` + 结论行 `T=6.27`（18pt 黑体）→ 页脚发丝线 `T=7.00 H=0.005` → 页脚 `T=7.08 H=0.34`（14pt 极浅灰，结论行与页脚线保持 0.29in）。
- 页眉页脚固定写法：页眉横线**上方**左侧写章名（如"第一章 研究动机与背景"），右侧可放标注（如"虚构示例"）；页脚横线**下方**左侧写汇报标题、右侧写页码（如 `03 / 06`）。页眉页脚一律浅灰，视觉权重必须低于正文。
- 框高按字号反推：单行需要 `字号 × 1.2 × 1.18`，20pt 至少 0.46in、18pt 至少 0.42in、16pt 至少 0.38in；照抄旧稿的 0.28–0.36in 小框会被判溢出。
- 默认**左文右图双栏**（左约 6.7in、右约 5.4in、间距 0.2in）：左栏 = 3 条实证纯文字行（18pt，行步进 ≥0.85in，关键数值黑体墨色）→ 发丝线 + 黑体判断行（18pt，不带"判断："前缀）；右栏 = 横向条形图（按数值排序 + 浅灰网格线与刻度，只点亮一根）+ **两行图注**（第一行写结论句，第二行写口径句，均 16pt 次级灰）。
- 结论行**不带"结论：/判断：/收束："前缀**（含页面标题，机审按全文出现次数强制为 0），直接写判断句；只出现在真正有结论的页，不必每页都有。
- **口径声明收敛**："虚构/示例"字样全片 **≤4 次、最多两处声明位**（机审强制）——封面副标一处、数据页表注一处；页眉不放角标，正文副标不复读。
- **强调不用色块**：判断与结论用发丝线 + 黑体墨色；关键数值用黑体；图表只点亮最重要的一根柱或一行，其余保持中性灰。

## 内容与备注
- 数据只来自用户提供的材料（Word/课件/来源文件），不编造、不自造词；旧数据按材料里的最新口径更新。
- 数据来源、口径、备答写进**备注**，不上片。
- 每页备注写约 1 分钟逐字稿，可含口径备答。

完整分阶段流程（接单 → 材料 → 版式 → 生成 → 三道自检 → 交付）见 `references/workflow.md`；出现返工触发条件时按该文件处理。

## 字符与记号（避免豆腐块与歧义）
- 中文字符一律限制在 **GBK 可编码范围**：宋体/黑体/楷体都能覆盖 GBK，超出就可能出现豆腐块。交付前用 `scripts/audit_ppt.py` 的"字形缺失"项兜底。
- **数学上下标写成 ASCII**：`V^T`、`σ1`、`σi`、`1e-8`、`O(nk^2)`；不要用 `ᵀ`、`₁`、`²`、`⁻⁸` 这类字符（宋体很可能没有）。
- 生成脚本里的**强调标记不要用 `[[ ]]`**（会与矩阵记号 `[[1,2],[3,4]]` 冲突），用 `{{ }}`。
- 公式块优先用"大字 + 短句"表达，不要用长行 ASCII 公式。

## 图表与几何细节
- 数值标签设为外侧端点（OUTSIDE_END）且**轴从 0 起**时，轴上限设为最大值的约 1.2 倍，否则标签贴边或被裁。
- **截断数值轴要诚实**：量纲相同、数值拥挤时允许截断窗口（如 `0.60–0.90、步长 0.05`、刻度格式 `0.00`），但**必须在图注写明"数值轴 X–Y，截断显示"**，结论句照常写"领先约 N 个千分点"这类真实量级——不许用截断制造断层假象，也不许假装没截断。
- 类别多时（≥4 类）柱宽要留间隔，避免柱子挤成一条线；条形图同理。
- 散点图把 `scatterStyle` 设为 `marker`，否则默认会带连线。
- 图表配色：整根系列用中性灰 `BFBFBF`，只把最重要的一根柱（或表格里关键一行）设为点缀色 `0072B2`；数值标签墨色不加粗，轴线用发丝线。
- 对比类图表优先**横向条形图并按数值排序**，打开数值轴（0 到上限）与浅灰网格线让差距可读；零基线柱状图会压缩差异，"只点亮一根"必须建立在"差异可见"之上。
- 同一页里所有形状的坐标以 **0.05in 为网格对齐**，视觉才成体系。

## 交付与安全
- 需要改单页时**单独输出一个 pptx**，不覆盖用户正在编辑的源文件。
- **绝不调用 PowerPoint COM 或操作用户打开的窗口**，只做文件读写。
- 改完先出预览图给用户确认，再提交；用 `scripts/verify_ppt_style.py` 校验字号、配色与对比度，用 `scripts/preview_ppt.py` 生成 HTML 预览（截图用 headless Chrome，命令见上文）。
- 纳入版本管理时只提交本次新增/修改的交付文件，不提交用户自己在改的文件；中间产物放临时目录并忽略。
